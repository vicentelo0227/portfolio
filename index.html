看得見的打開就能用的網站

森林漫步Forest Walk

互動式沉浸網站

一個可以在瀏覽器裡散步的森林。沒有分數也沒有計時，點擊畫面中發光的地方往前走， 沿途會經過幾個可以停下來聽音樂的地方。關掉分頁明天再回來，會記得你走到哪裡。

我做了什麼
視覺設計、互動流程、前端實作到自動部署全部一人完成。 11 個場景分主線與支線，6 個停留點各有專屬配樂。
比較難的地方
要讓人感覺不到技術的存在。影片背景用雙層交叉淡入消除循環接縫； 環境音以分貝換算音量後疊加，讓溪流、鳥鳴、林風同時存在卻不互相蓋過。
技術
Vue 3、Vite、Pinia、Tailwind CSS、Howler.js、GitHub Actions 自動部署

物候線上商店示範

可實際操作的購物流程

一間虛構器物店的完整購物流程。選規格、加入購物袋、改數量、走完結帳——每一步都是真的可以點的。 關掉分頁明天回來，購物袋還在。

為什麼做這個
想做購物網站的客戶，看報價單看不出結果會長怎樣。這支讓他直接用手機點過一輪， 比任何簡報都清楚。
裡面有什麼
規格沒選完之前購買按鈕不會出現；缺貨分成「暫時沒貨」和「不生產」兩種說法； 運費在購物袋就算給你看，不會等到最後一步才冒出來；結帳不用註冊會員。 這些都是拆解 Apple、Dyson、Amazon 等站的實際做法之後決定的。
技術
原生 HTML／CSS／JavaScript，無框架無建置流程，狀態存在瀏覽器。全站 676 KB

B'Mushsoft music

內容網站，上線營運中

一個關於慢音樂的網站，有文章、播放清單與訂閱電子報。 從網域、佈景、內容到後續維護都是自己來，現在每週固定更新。

我做了什麼
自己寫了一套 WordPress 區塊佈景主題（不是套用現成模板）， 包含版面配置、色彩系統、字體與各頁模板；並建置本機開發環境，改好測過才上線。
為什麼這件事跟你有關
如果你要的是一個能自己更新內容、不用每次都回來找工程師的網站，這就是我實際在做的事。 我不只把網站交出去，我自己也在經營一個。
技術
WordPress 區塊佈景主題、theme.json 設計系統、本機開發環境與部署流程

有些東西沒有畫面，但它每天準時做完一件本來要花你一小時的事。 這類系統占我工作的一大半。

新聞自動彙整系統

每日自動執行，無人介入

每天固定時間自動抓取多個新聞來源，用 AI 判讀重要性與摘要內容， 整理成報告發到 Slack，同時完整存進 Google 試算表備查。 AI 新聞每天早上八點、台股每個交易日傍晚六點、美股每個交易日晚上十點。

解決什麼問題
原本要人每天花時間翻新聞、判斷哪些重要、再整理給大家看。現在這件事沒有人需要做。
技術
Python、RSS 多來源整合、LLM 分析、Slack Block Kit、Google Sheets API、GitHub Actions 排程

原始碼

台股當沖策略系統

個人專案，原始碼未公開

接券商 API 取得即時報價，依設定好的規則判斷進出場，同時管理部位與風險上限。 另外有一套獨立的回測工具，可以先用歷史資料驗證策略再上線。

為什麼放這個
這類系統出錯就是真的賠錢，所以架構必須乾淨、每一層都要能單獨測試。 報價、策略、部位、風控、下單各自獨立，換掉其中一層不會動到其他部分。 這正是我做任何後端系統的方式。
技術
Python、券商 API 串接、分層架構設計、回測框架、狀態管理與風控規則

動畫批次渲染工具

影音製作工具

丟進一個動畫檔，自動生出 30 種配色版本，再串成一支長循環影片， 版本之間平順轉場，輸出可直接進剪輯軟體的透明背景格式。 用多核心同時算，把原本要等很久的事縮短。

解決什麼問題
原本要在動畫軟體裡手動改色、逐一輸出、再自己接起來，重複三十次。現在一行指令。
技術
Node.js、Worker Threads 多核心平行處理、Lottie、FFmpeg、ProRes 4444 透明輸出

可以找我做什麼

  • 網站開發 形象官網、活動網頁、產品介紹頁。可以從版面設計到實作全包，也可以依你既有的設計稿實作。手機版一定會做好。
  • 網站架設與搬家 WordPress 架站與客製佈景、網域與主機設定、既有網站搬家。交付後你自己就能更新內容。
  • 流程自動化 把每天重複做的事變成自動執行：定時抓資料、自動整理報表、串接 Slack 或 Google 試算表通知。
  • 系統與 API 開發 後端 API、資料庫設計、金流與第三方服務串接、後台管理系統、爬蟲程式。
  • 接手與改善 網站很慢、功能壞掉、前一個工程師交接不清楚。這類沒人想接的案子我也承接。
  • 教學與 AI 導入 一對一程式教學；或是帶團隊把 AI 工具真的用進日常工作流程，不是看完就忘的講座。
